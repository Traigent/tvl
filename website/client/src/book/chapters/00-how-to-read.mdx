<h2 id="how-who">Who it is for</h2>

This book is for engineers who build or run AI agents and want to write down, in one file a machine can check, what an agent may change, what is allowed, and what counts as an improvement. You should be comfortable with YAML and a terminal. You need no background in machine learning, statistics or formal methods: each idea is explained where it first appears.

<h2 id="how-need">What you need</h2>

- Python 3.12 or newer, and git.
- A terminal with bash or zsh, on Linux or macOS. On Windows, use WSL.
- For chapter 13, on your own agent: your own evaluator and an evaluation set.

Chapter 2 installs the tools, at the commit this book was tested with.

<h2 id="how-chapters">How the chapters work</h2>

One running example, a support bot for an online shop, grows a little in every chapter. Each chapter opens with "What you'll learn", then repeats four steps:

1. **Learn.** A situation you will recognise, then the TVL that captures it.
2. **Predict.** A "Predict first" box asks a question before the book answers it. Write your guess down before you read on.
3. **Run.** A "Try it" box gives commands to run and the output to expect. Each example file is checked by the book's tests against the result printed under it, and printed outputs are exact: yours should match them. The one exception is a solver's answer, a witness (one allowed design) or an UNSAT core (rules that contradict each other), where another valid answer may appear; those blocks say "One possible output". Some examples fail on purpose, and say so.
4. **Explain.** The text explains the result. A "You might think…" box takes on a common misunderstanding.

Each chapter closes with "Key takeaways".

<h2 id="how-web-pdf">Web and PDF</h2>

The web edition, at tvl-lang.org/book, and the PDF are built from the same source.

- **Figures.** On the web, figures are animations with a play button. In print, each becomes a numbered sequence of still frames with captions.
- **Answers.** On the web, "Show the answer" reveals a prediction's answer. In print, the answers are at the end of each chapter.
- **Sources.** On the web, references to TVL's normative documents are links. In print, they are numbered, such as [1], and listed at the end of each chapter with their full addresses, each pinned to a commit. They are optional reading.
- **Glossary.** On the web, a term with a dotted underline opens its definition when you hover over it, focus it or tap it. In print, a small raised "g" marks the first use of a term in each chapter, and the Glossary at the back defines it.

<h2 id="how-conventions">Conventions</h2>

- Command blocks show only what you type, with no `$` prompt in front, so you can paste each line as it is.
- Run every command from the root of the repository: the `tvl` folder you clone in chapter 2. Paths such as `spec/examples/book/ch02/support-bot.tvl.yml` start there.
- The tools count from 0: `constraints.structural.0` is the first rule.
- Chapters 9 to 12 describe TVL 1.3, accepted as version 1.3.0 on 21 October 2026 (<Ref to="rfc-0003">RFC 0003</Ref>).

<h2 id="how-edition">This edition</h2>

This is the complete edition: chapters 1 to 13. Chapters 9 to 12 follow the accepted TVL 1.3 specification; chapter 13 shows how to start on your own agent. No other chapters are planned.
