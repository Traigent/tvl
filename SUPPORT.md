# Support

## Questions

Ask questions in [GitHub Discussions](https://github.com/Traigent/tvl/discussions/categories/q-a) (Q&A). Ideas that are not yet a concrete proposal go in the [Ideas](https://github.com/Traigent/tvl/discussions/categories/ideas) category.

## Bugs and spec changes

Open an issue at <https://github.com/Traigent/tvl/issues> and choose the form that fits:

- **Bug report** for a wrong result, crash or confusing diagnostic from a tool for TVL, the Tuned Variables Language.
- **Spec change** for a gap, ambiguity or proposed change in the language. Larger changes follow the [RFC process](formalization/README.md).
- **Documentation** for something missing, unclear or wrong in the docs.

Before opening an issue, search the existing ones, and check the [error code catalog](docs/reference/error-codes.md) if you are looking at a diagnostic.

Do not paste secrets, credentials or customer data into an issue. Redact a module before sharing it.

## Documentation

The language specification and worked examples are at <https://tvl-lang.org>. More guides and the error-code catalog live in this repository under [`docs/`](docs/) and [`spec/`](spec/). Start with [Getting Started](docs/getting-started.md).

## Security

Report vulnerabilities privately, as described in [SECURITY.md](SECURITY.md). Do not open a public issue for them.

## What is not offered

There is no chat channel. Maintainers answer on a best-effort basis; there is no service-level agreement and no promised response time.
