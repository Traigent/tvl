`tvl-compose` checks these narrowing rules, within the limits given in the last column:

| Override Type | Allowed | Not Allowed | Checked only when |
|--------------|---------|-------------|-------------------|
| Enum domain | Remove values | Add new values | both base and overlay domains are plain lists (a `set:` wrapper or a change of domain shape is not checked) |
| Numeric range | Narrow bounds | Widen bounds | both domains are mappings with `range` |
| Budget | Decrease | Increase beyond base | the key (`max_trials`, `max_spend_usd` or `max_wallclock_s`) is present in both; removing a budget is not checked |

<ConceptCallout title="Current Validation Scope" tone="info">

The current implementation validates enum narrowing, range narrowing, and budget decreases. It also
rejects an overlay that drops a structural or derived clause of the base, unless the overlay restates
it, replaces it with a strictly tighter bound on the same symbol, or declares a waiver with a reason
under `_tvl_overlay.waives`. A waiver records a human decision; it does not prove the clause was
vacuous. (A clause is vacuous when it can no longer restrict anything. For example, narrowing a range can make the `when` condition of an implication impossible, so the rule never applies.) Resolution changes are merged without validation, so keep them to safe narrowing.

</ConceptCallout>
