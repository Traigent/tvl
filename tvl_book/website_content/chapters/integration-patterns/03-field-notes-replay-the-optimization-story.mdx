The Orientation RAG lab is a simulation: it computes illustrative latency, cost, and quality numbers in the
browser. It does not run TVO or DVL. Jump between **Baseline**, **Latency Spike**, and **Budget Shift** to see the
kind of trade-off an optimizer has to weigh and the kind of guardrail a data-validation step checks.

<MicrosimEmbed title="Orientation RAG Circuit" src="/book-assets/microsims/orientation-rag-circuit/main.html#budget-shift" height={640} />

- Compare the latency and cost read-outs before and after each preset.
- Click **Copy YAML** to capture a simulation snapshot of the slider values. It is not a schema-valid TVL
  configuration or a TVO export.
- The badges test simple latency, cost, and rerank thresholds. A real promotion gate also requires a valid
  configuration, passing behavioral checks, and statistical evidence of improvement from real measurements,
  followed by deployment review. Green badges are not that evidence.

<ConceptCallout title="CI Recipe" tone="integration">

```bash
# 1. Validate the spec
tvl-validate path/to/spec.tvl.yml

# 2. Check constraints are satisfiable
tvl-check-structural path/to/spec.tvl.yml

# 3. Run optimization (illustrative: Triagent is an external CLI, not part of this repository)
triagent optimize --spec path/to/spec.tvl.yml --output results/

# 4. Validate promotion candidate
tvl-measure-validate path/to/spec.tvl.yml results/config.yml results/measurements.yml

# 5. Run promotion gate (compare incumbent vs candidate)
tvl-ci-gate path/to/spec.tvl.yml results/incumbent.yml results/candidate.yml --json

# 6. Data quality check (illustrative: DVL is an external CLI, not part of this repository)
dvl validate suites/faq-orientation.json
```
